# Pbiomon 物种小类训练方案与记录

目标是比较现网模型微调、YOLO11m 重训、YOLO26m 重训三条路径。三组共用同一版全量合格训练集、类别映射和评估集。小类是框级「物种 × 性别 × 年龄」，保留接口明确标注的“无法区分”。缺失值、群体属性以及没有框级依据的属性进入复核。

## 实验约定

| 组别 | 初始化 | 训练集 | 对照目的 |
| --- | --- | --- | --- |
| 现网基线 | 现网对应的物种 `best.pt` | 冻结权重 | 量化旧场景回归和新场景收益 |
| A | 现网物种 `best.pt`，使用新优化器和学习率计划 | 全量合格老数据＋新数据 | 保留领域权重并纳入新样本 |
| B | 官方 COCO 预训练 `yolo11m.pt` | 与 A 相同 | 比较同架构下物种权重热启动的效果 |
| C | 官方 COCO 预训练 `yolo26m.pt` | 与 A 相同 | 在目标数据和 T4 上比较换代收益 |

同组中断恢复使用自己保存于 `continuations/epoch-*/last.pt` 的检查点，核对实验摘要并恢复优化器、AMP scaler、验证记录和同期最佳权重。三组固定输入尺寸、训练样本、增强、有效 batch、验证口径和最大优化器步数。三组已共用 Ultralytics 8.4.220、PyTorch 2.4.1、CUDA 12.4，在单机双卡上通过 FP16 AMP 接续短测。统一 640 输入，先用实际混合集短跑测显存和吞吐，再定正式 batch 和轮次。记录训练配置、数据版本、初始化权重摘要、最佳验证步数和 GPU 小时。 [YOLO 训练文档](https://docs.ultralytics.com/modes/train/)

## 数据加工与评估

1. 旧库位于 `image3:/mnt/data2/all_species_240916/animal_action`，保留原媒体和标签。验证相同名称的训练/验证样本的内容，对跨集合的近重复和同一拍摄事件分组。利用 `no_target`、`human_action` 做未配标签图片的来源核验。若评估和训练仍包含人的检测类别，含人但缺框的图进入补标复核。
2. 新库位于 `image0:/mnt/data2/pbiomon_yolo`，冻结已采集数据、逐资源媒体摘要和逐物种标注版本。按尺寸、EXIF 方向、监测单元、拍摄时段核对参考画面和坐标变换。使用可验证的框与鉴定项关联，视频框必须对齐原解码帧和时间。保留无法转换、缺框和冲突原因，避免把漏标动物作为背景。详见 [归档和导出规则](pbiomon-download.md)。
3. 类别注册表初版保留现网 1,167 个小类 ID，明确记录新库 `speciesId` 与旧名、性别、年龄的映射。经核准的新小类在末尾添加，并在 A 中核对旧检测头是否按旧 ID 保留。数据冻结后输出 `data.yaml`、`classes.json`、样本清单、逐类计数和排除表。所有通过验收并划进训练集的样本都纳入。
4. 冻结旧场景回归集与新独立测试集。旧回归集剔除历史训练同图及同场景近重复事件；新独立测试集按站点、拍摄事件和原视频分组，核对旧模型训练暴露。只用验证集选权重与阈值。最终在相同测试集比较现网和 A/B/C。
5. 主指标为小类 `mAP50–95` 和固定阈值宏平均 F1。核对旧核心类召回、新站点、昼夜、小目标、长尾、照片和视频、背景误报，记录有真值的类别数和每类样本量。在同规格 T4 上测 TensorRT 输出和 P95 延迟。初始验收建议为新场景指标改善、旧核心类召回下降不超过 2 个百分点，背景误报和延迟满足现网预算。正式训练前冻结指标口径和门槛。

### 冻结后的执行入口

扩类输入是一组已验收条目，每条包含原库 `species_id`、核定物种名 `species`、标准化 `gender` 和 `age`。类别工具以最近一版注册表为起点追加，导出数据时将相同的 ID 和名称写入 `data.yaml`。

```bash
python3 tools/pbiomon_classes.py extend \
  --legacy-registry "$previous_registry" --approved "$approved_classes" \
  --out "$candidate_classes"
```

在可读取两份源媒体的训练机器上导出，保留快照标注、逐类图片及框数、排除记录、逐样本摘要和旧场景／新场景测试清单。新库复核输入为 JSONL，每行对应一个资源，包含 `type`、`resource_id`、`media_sha256`、`bundle_sha256`、`split`、`group_id` 和 `frames`。统一拍摄事件或近重复组使用同一个 `group_id`，验证和测试记录提供对历史训练暴露的核对证据。与历史训练同名的照片另附内容复核证据。

每个帧记录包含实际显示宽高 `display_size`、复核依据 `review_evidence` 和完整覆盖标记 `complete`。照片的 `frame_id` 和 `ts_ms` 均为 `null`。视频使用原始帧序与时间戳。每个框记录提供 `species_id`、源 `box_index`、已确认的 `attribute_index`、标准化 `species/gender/age`、`coordinate_evidence` 和 `association_evidence`。

框坐标可提供显示像素 `xyxy`，或明确审核通过的 `coordinate_space`。照片的 `raw_65536` 和 `raw_pixels` 分别指定旧标尺和原图像素，程序依据实际照片 EXIF 同步旋转框与图。`display_pixels` 适用于已核对在显示图或解码帧上的像素坐标。导出清单记录计算结果。独立补标的框或属性将对应下标填为 `null` 并附依据。

旧库回归批准清单的每行包含 `sha256` 和 `exposure_evidence`，可通过 `split` 指定验证或测试，默认测试。
